# ELESEND — deeper source audit, remediation and release-gate record

**17 October 2026 · Reviewed input:** `ELESEND_CASH_FIRST_MOBILE_DISPATCH.zip` (provided in this conversation). The input archive was treated as immutable. This candidate is an **Android/iOS app + standalone JSON API modular monolith**; it does not depend on ELEMARKET, and the server may run on any suitably configured VPS or cloud VM. **RELEASE HOLD — DO NOT PROCESS PUBLIC REAL MONEY.**

## Confirmed source defects repaired in this candidate

| Risk | Original defect and likely consequence | Precise remediation | Evidence level |
|---|---|---|---|
| HIGH — financial integrity | `platform.verify` permitted a zero or partial rider cash report to precede successful recipient OTP and booked the full ELESEND commission; `cash_rider_reported` could imply fully collected money where none was reported. | Require `reported_full` for **ordinary** cash handover and successful delivery; other reports remain immutable evidence but require dispute/failure/return resolution. New database trigger `010_cash_custody_guards.sql` independently protects state transitions and refuses to migrate a historical dataset containing inconsistent prior completed/collected events. | Source verified; database execution **BLOCKED**. Added regression scenario. Cash remains unverified physical rider assertion, not confirmed PSP receipt. |
| HIGH — assignment | `dispatch.release` reset an uncollected shipment but left `dispatch_commitments` owned by its former rider. A subsequent rider accepting the same shipment could fail on the `shipment_id` primary key. | Delete that old rider's commitment **inside the same release transaction**; append-only audit/offer rows preserve evidence; new rider creates its own deadline. Added DB regression test for release → different rider → accept → one fresh commitment. | Source verified; integration **BLOCKED**. |
| HIGH — payment reconciliation | When two separately initiated PSP repayments were genuinely confirmed but the second exceeded debt remaining after the first, the original handler rolled back recognition of the second real provider payment. | Post the amount backed by valid obligations to commission collection; record the residual as distinct `unapplied_provider_funds` liability. It never turns into rider prepaid credit or platform commission automatically. Add immutable double-entry kind `commission_overpayment`, rider visibility, and deterministic DB regression. | Source verified; real PSP integration **BLOCKED**. Separate payment events for the *same* provider transaction remain a reconciliation gate. |
| MEDIUM — revenue policy | Due dates were displayed but not enforced; a rider could keep accepting additional cash jobs after a commission repayment deadline, subject only to amount/job limits. | Add bounded, administrator-configurable per-rider `grace_days` (0–30) and reject **new cash offers** when an obligation is past due + grace. Existing custody is never interrupted. | Source verified; DB policy tests **BLOCKED**. |
| HIGH — deployment credentials | `.gitignore` and `.dockerignore` excluded `.env` but not `.env.vps` or `.env.production`; an operator could accidentally commit secrets or add them to a Docker build context. | Exclude secret `.env.*` and nested env files; keep safe checked-in `.env.example` files; remove unnecessary mobile source copy from backend Docker image. | Static inspection **PASS**; Docker build **BLOCKED**. |
| HIGH — availability | The root `compose.yaml` forwarded host port 3090 to API while the API listened on `127.0.0.1` **inside** the container, breaking access through the Docker network. | Set API process `HOST=0.0.0.0` in Docker config; keep port published to `127.0.0.1` on the physical host. | Static inspection **PASS**; container network **BLOCKED**. |
| MEDIUM — monitoring and DoS | Anonymous `/health` executed `SELECT 1` with no IP limiter, enabling inexpensive unauthenticated repeated DB checks. | Make `/health` a DB-free liveness check. Optional `/ready` performs DB query only after checking a private, 32+-character timing-safe monitoring token. | Source verified, runtime load **BLOCKED**. |
| MEDIUM — riders behind ingress proxy | IP rate limits used `socket.remoteAddress`; behind a single reverse proxy this lumps all rider traffic under one 300/min limit. Naively trusting `X-Forwarded-For` would enable IP-spoof bypass. | Add explicit trusted-proxy IPv4 CIDR/exact-IP parser and right-to-left, untrusted-hop selection. Default does **not** trust forwarded headers. 4 passing unit tests cover forged/malformed/multi-hop headers. Verify actual ingress IP and CIDR on staging. | Unit tests **PASS**; deployment config and load **BLOCKED**. |
| MEDIUM — native UX | Expired or disconnected rider sessions could prevent mobile logout because the remote revoke threw before local token/cache cleanup. | Place local token/cache deletion and UI clearing in a `finally` block, even if server revoke fails. Note: offline server-side revocation cannot be guaranteed; server sessions expire after 12 hours. | Source/JSX parse **PASS**; real devices **BLOCKED**. |
| ARCHITECTURE | Deployment samples and active instructions were named for one VPS vendor. | Remove vendor-specific deployment directory, move templates to **`deploy/vps`**, document any generic Linux VPS/cloud VM, keep DB/routing/messaging/payment provider contracts isolated. Node backend runs behind HTTPS; there is NO customer website. | Source/static inspection **PASS**; provider portability **BLOCKED** until deployed on two environments. |

## Other vulnerabilities, gaps, and claims **not fixed or not yet verified**

**CRITICAL — release blockers**
- Production `server.mjs` has **no configured SMS adapter**. Mandatory pickup and recipient OTP delivery cannot function for real users, by design. Do not short-circuit OTP for a launch.
- `financeService` has no live authorized Ghana payment-provider adapter. Commission MoMo repayment remains disabled; screenshots and app callbacks are not settlement proof. Verified, duplicated or out-of-order PSP events, clearing accounts, fee reporting, refunds and reversals need provider-specific certification.
- PostgreSQL/PostGIS engine was unavailable. Migration 010, earlier migrations, cash OTP triggers, row locks, journal balancing, account overpayments, rider commitments, backup integrity, and simultaneous acceptances were **not executed** on a real DB in this environment. Keep multi-stop pooling OFF until tested.
- Merchant **merchandise COD** collection/remittance is NOT implemented; the collection field is for delivery charges only. Ghana legal/commercial/insurance and vehicle-KYB/KYC evidence require review.
- The Expo app is React Native source, **not a signed APK or IPA**. Android/iOS device, background GPS, storage, and SMS end-to-end tests have not been executed.

**HIGH — requires follow-on engineering**
- No independent cash payment attestation. A rider can lie and report “full”; OTP proves authorized handover workflow, **not physical cash receipt**. Implement customer receipts/acknowledgement and dispute evidence while preserving rider fair process. Ordinary delivery now fails closed if rider reports shortfall, but partial collection cannot yet be incrementally topped up through a self-service workflow.
- No outbox delivery consumer with retry/dead-letter workflow and no realtime push dispatch acceptance notification. The app has polling only and limited offline recovery.
- No real vehicle document uploads, independent identity/phone ownership attestation, anti-spoof mobile integrity evidence or app attestation. Car records are manually marked approved without true document review in this build.
- User signup lacks phone ownership verification; admin financial operations lack MFA, granular approval evidence and a secure disaster-recovery routine. Strict SQL roles for migration versus runtime are not separated.
- Payment provider initiated intents may remain pending without reconciliation/sweeper; one provider payment may generate multiple event IDs. Unique provider **transaction references** plus replay/out-of-order handling and suspense investigations must be verified with each live adapter.
- Google Maps/Routes per-vehicle road coverage, time-dependent direction, ETA calibration, congestion data, route matrices and matrix quotas **have not been exercised on Ghana roads**. No straight-line routing fallback is permitted for quotes or assignment.
- Quote pricing still uses the road distance for a `car` routing profile regardless of actual dispatch vehicle. Full per-vehicle quoting, cost and margin policy, staged ETA calibration and parcel dimensions remain incomplete.
- No objective production latency, database/routing cost, backup restoration or load/soak evidence; do not infer operating capacity from microbenchmarks.

**MEDIUM — configuration and operational controls**
- Trusted proxy IP/CIDR must be deliberately configured for an exclusive ingress proxy; default direct-peer throttling can still aggregate clients on a reverse proxy. IPv6 CIDR trust is not supported (exact IPv6 is).
- Redis is optional; authoritative data remain in PostgreSQL. No provider-neutral VPS is **actually deployed**. Follow infrastructure capacity, offsite backup restoration, GPS retention and privacy request implementation before launch.
- Scrypt token/password protection exists in code but independent security, regulatory, static dependency advisory (online), iOS/Android secure storage, network abuse and DDoS reviews remain outstanding.

## Reproducible verification performed (this remediation)

- Node **22.16.0**; `npm run test:unit`: **25 passed / 0 failed**. Tests are deterministic and/or use mocked Routes HTTP; they are **NOT** evidence of a functioning PostGIS environment, PSP collection or live Ghana route accuracy.
- All backend `.mjs` and test modules passed Node `--check` syntactic parsing. React Native `App.js` plus `src/api.js`, `src/offline.js`, `src/tracking.js` passed TypeScript JSX *syntax transpilation* with zero parse diagnostics; **not** APK compilation.
- PostgreSQL/PostGIS integration tests **not run**, because no local server exists; `npm ci` could not retrieve registry archives over network in this environment. A prior `npm test` attempt failed to load missing Node dependencies; current successful standalone unit tests do not hide this limitation. Historical records bundled under `documentation/` are **not** evidence for this exact package.
- Build target remains platform-neutral mobile APIs + portable Linux VPS/docker template. Production PSP/SMS and outbound push capabilities deliberately fail closed without adapters and credentials.

## Deployment order

1. Backup and inspect a staging DB, confirm it is disposable (`elesend_test*` for destructive test suite). Run all tracked migrations including 010; investigate any historical cash migration exception before proceeding.
2. Run `npm ci`, `npm run test:unit`, `npm run test:db`, `npm test`; verify real concurrent acceptance/reassignment, double-entry invariants, commission payment handling and cash dispute flow. In the absence of passing DB tests, **DO NOT release**.
3. Obtain separate approved SMS and payment-provider test credentials, configure HTTPS API, restrict readiness secret and reverse-proxy CIDRs; exercise signed webhooks and live device OTP without shortcuts.
4. Build native Android/iOS binaries; test shift tracking, offline/recovery, actual Ghana roads, dynamic car/bike policies, and operator controls on physical devices.
5. Exercise offsite backup **restore**, disk pressure alerts, security penetration tests, privacy retention, incident response, charge disputes and Ghana legal/commercial review before pilot activation.

**Bottom line:** This artifact contains tested stand-alone unit behavior plus material source repairs. It has **not** passed production release gates, real database tests, mobile builds, live route verification, SMS delivery or financial provider reconciliation.
